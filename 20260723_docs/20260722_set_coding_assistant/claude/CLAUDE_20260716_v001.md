## What this project does

A Google Form auto-reply service. It polls one or more Google Forms for new responses, extracts
the respondent's email (and phone number) from configured question titles, validates the email
format, and sends a notification via the Gmail API using a per-form mail template. Runs as a
long-lived loop (default: every 300s) so it can operate unattended, packaged as a Docker container
with `restart: unless-stopped`.

- **Auth**: a single Workspace service account (key at `configs/*.json`, gitignored — never
  commit it) impersonates `biz@sumokhoe.co.kr` via domain-wide delegation (approved in the
  `admin@sumokhoe.co.kr` Workspace admin console) to call both the Forms API
  (`forms.responses.readonly`, `forms.body.readonly`) and Gmail API (`gmail.send`). Shared across
  all forms.
- **Core module**: `src/app/procedure/google_form_auto_reply.py` — `GoogleFormAutoReply` holds the
  shared credentials/API clients and a list of `_FormTarget` (one per form: form ID, question
  titles for email/phone, state file, mail template dir). `check_once()` loops over every form
  target, doing one poll/validate/send cycle each (a failure in one form is caught and logged, not
  fatal to the others); `run()` loops `check_once()` forever. Each form's processed responses are
  tracked in its own CSV state file (`index, response_id, answer_email, answer_phone,
  mail_send_success, mail_resend_success, mail_third_send_success, answer_fix_email,
  time_first_send_attempt`) inside its `mail_template_dir`, so restarts don't resend.
  `answer_fix_email` defaults to `'nan'` and is only ever set by `__resend_with_domain_fix` (see
  the resend-retry bullet below), to the corrected address it attempted — on both send success
  and send failure, since either way a fix-and-resend was attempted with that address.
  **First-run safeguard**: if a form's state file doesn't exist yet when the process starts
  (`_FormTarget.is_first_run`), that initial batch of responses is written to the CSV without
  calling `__send_mail` — only responses seen on later poll cycles actually get mailed. This
  exists because on 2026-07-15, moving the garmin/nutrition state files to a new path caused the
  entire historical response backlog to look "new" and get mass-mailed (151 real emails sent
  before it was caught). Any brand-new form, or any form whose state file path/format changes
  again, relies on this to not repeat that incident — don't remove or bypass it without
  understanding why it's there. Each response row also records `mail_send_success`: `True`/`False`
  once a send was actually attempted (`False` also covers rows skipped as duplicates — see the dedup
  bullet below), or the string `'nan'` for first-run-seeded rows where sending was skipped entirely
  (not a real true/false outcome). `time_first_send_attempt` is the epoch timestamp of that first
  attempt (`'nan'` for first-run-seeded rows and duplicate-skipped rows alike, since no attempt was
  made in either case).
- **Same-email dedup across submissions**: new-response detection (`__get_new_responses`) only
  dedups on Google's own `response['responseId']` — it has no notion of the answer email, so the
  same person submitting the form twice with the same email (regardless of whether other answers
  like phone differ) would otherwise produce two separate response IDs and two separate mail sends.
  `_FormTarget.set_mailed_email` closes this gap: a lowercased set of every address considered
  "already known" for that form — populated from real sends (`add_processed_record`, when
  `mail_send_success` is `True`), first-run-seeded rows (`add_processed_record`, when
  `mail_send_success` is the string `'nan'` — a deliberate choice: an address seen even in the
  never-mailed historical backlog is still treated as known, so it won't be mailed on a later
  resubmission either), plain resend (`__resend_plain`), and domain-fix resend
  (`__resend_with_domain_fix`, which adds both the original and the corrected address, since the CSV
  only ever persists the original). In `__process_form_once`, a new (non-first-run) response whose
  email is valid and already in this set is recorded with `mail_send_success=False` and
  `time_first_send_attempt='nan'`, and `__send_mail` is never called for it. Using the same `False`
  value as a real failed send is intentional (see below for how it stays safe), rather than a
  distinct sentinel. Comparison is case-insensitive.
  Persistence: each form's set is written to its own `mail_template_dir/mailed_email.txt` (plain
  text, one lowercased address per line — chosen for the simplest possible read/write path, same
  convention as `unique_email_domains.txt`) via `_FormTarget.save_mailed_email()`, called after every
  processed response in `__process_form_once` and after every state-changing pass of
  `__resend_failed_mail`. This file is the source of truth once it exists; `_FormTarget.__init__`
  only falls back to rebuilding the set from the CSV's history (rows with `mail_send_success` `True`
  or `'nan'`, or `mail_resend_success`/`mail_third_send_success` `True`) the first time it doesn't
  exist yet, so upgrading to this feature doesn't forget who was already mailed (or already seeded).
  Like `processed_response_id.csv`, this file holds real respondent emails (PII) and is gitignored,
  not tracked.
  **Why reusing `False` for duplicates is safe**: `__resend_failed_mail` only acts on rows where
  `time_first_send_attempt` is not `'nan'` — since duplicate-skipped rows always keep it `'nan'`
  (no attempt was ever made), they can never be picked up by the resend-retry scan even though their
  `mail_send_success` reads `False` exactly like a real failed send. The domain report separately
  only counts rows where `mail_send_success` is `True`, so duplicate-skipped rows are excluded there
  too, same as real failures. The CSV's `answer_fix_email` column closes what was previously a known
  caveat here: across a process restart, a row that only succeeded via `__resend_with_domain_fix`
  used to be reconstructable only from the CSV's original (typo'd) `answer_email` if
  `mailed_email.txt` was somehow lost — the corrected address that actually received mail was
  otherwise guaranteed to survive only via the persisted file, not the CSV. Now `_FormTarget`'s
  CSV-rebuild fallback also seeds the corrected address from `answer_fix_email` whenever
  `mail_third_send_success` is `True`, so it survives even without `mailed_email.txt`.
- **Resend retry (up to 3 total send attempts)**: every `mail_resend_interval_sec` (default 600s,
  `GoogleFormAutoReply.__resend_failed_mail`, called from `run()`), the process scans every form's
  in-memory processed-record list for rows where `mail_send_success` is `False`,
  `mail_resend_success` is still `'nan'`, and at least `mail_resend_wait_sec` (default 6h) has
  passed since `time_first_send_attempt`. There's no signal to tell "the address doesn't exist"
  apart from "some other error" — the Gmail API's `send()` accepts anything that isn't obviously
  malformed and only reports true delivery failure later as an async bounce to the sender's own
  mailbox, which nothing here reads — so the 6h wait plus a plain retry is a cheap proxy for
  distinguishing a typo'd domain from a transient failure that might resolve on its own.
  For each eligible row:
  1. `__resend_plain` retries the exact original `answer_email`, unchanged. Result goes into
     `mail_resend_success`. If this succeeds, the row is done — no further attempts.
  2. Only if step 1 fails, `__resend_with_domain_fix` corrects `answer_email`'s domain and sends
     once more. Two cases:
     - `answer_email` has an `'@'`: takes the part after it as the typo'd domain, finds the closest
       match among all known domains (`difflib.get_close_matches`, `cutoff=0.0` — always returns a
       match if the known-domain list from `path_email_domain_report` is non-empty, even a poor
       one), and rebuilds the address with that corrected domain.
     - `answer_email` has no `'@'` at all: `__find_domain_substring` scans the known-domain list for
       any domain that appears as a literal substring inside `answer_email` (case-insensitive,
       longest match wins on overlap); if found, everything before that substring becomes the local
       part and the address is rebuilt as `local_part@matched_domain`. If no known domain appears in
       the string, the row is skipped (`mail_third_send_success=False`, `answer_fix_email` stays
       `'nan'`) — same as when the known-domain list is empty.
     Either way, the rebuilt address is recorded in `answer_fix_email` and sent. Result goes into
     `mail_third_send_success`. This is the last attempt regardless of outcome — nothing retries a
     row again after this. `answer_fix_email` stays `'nan'` when this step is skipped entirely (no
     known domains yet, no known-domain substring match, or the corrected address still fails
     `EMAIL_REGEX`).
  Both steps together are what make a plain-retry failure look like "probably not a transient
  error" — but the domain fix still assumes the failure was a typo'd domain, not a bad local part,
  and will happily "correct" an already-fine-but-not-yet-`path_email_domain_report`-known domain to
  the closest known one.
- **Email domain report**: every `email_domain_report_interval_sec` (default 11h,
  `GoogleFormAutoReply.__write_email_domain_report`, called from `run()`), the process scans every
  form's in-memory processed-record list, collects the domain of `answer_email` for rows where
  `mail_send_success` is `True` (real sends only, not first-run-seeded, duplicate-skipped, or
  failed/skipped ones), and rewrites the dedup'd, sorted list to `path_email_domain_report`
  (`data/mail_template/unique_email_domains.txt`), one domain per line. Runs once immediately on
  process start, then every interval thereafter; the timer is in-memory only and resets on
  restart.
- **Config**: `configs/set_project.yaml` under the `google_form_auto_reply:` key. Top-level holds
  shared settings (service account path, subject email, poll interval, email domain report path/
  interval, mail resend scan interval/wait); `forms:` is a list, one entry per form (`key`, `form_id`, `question_title_email`,
  `question_title_phone`, `path_state_file`, `mail_template_dir`). Question titles are the exact
  Korean text as they appear on the live form (e.g. `'이메일 주소'`, `'전화번호(ex.01012345678)'`),
  not a fixed English label. Currently configured forms: `garmin` and `nutrition`, each with its
  own folder under `data/mail_template/<dir>/` containing `subject.txt`, `body.txt` (plain text,
  read verbatim as the Gmail message), and `processed_response_id.csv` (runtime state, PII —
  gitignored specifically even though the rest of `mail_template/` is tracked, see Git section
  below). `configs/env.py` is a secondary/legacy config surface (pre-dates this feature, mostly
  unused by it).
- **Entry point**: `main.py` calls `GoogleFormAutoReply(...).run()`. `LIVE.sh` runs it via the
  project's venv on this server.
- **`src/app/container.py` / `src/app/app.py`**: leftover dependency-injector wiring from an

## Testing

`tests/` covers `_FormTarget` CSV/mailed-email state load/save, the domain report aggregation, the
same-email dedup decision in `__process_form_once`, and the 3-step resend decision logic in
`google_form_auto_reply.py` — no Forms/Gmail API calls are made; tests
either need only local files (`_FormTarget`) or construct `GoogleFormAutoReply` via
`__new__` (skipping `__init__`, which needs real service-account credentials) and monkeypatch the

Docker image) and run:
```bash
venv/bin/pip install -r requirements-dev.txt
venv/bin/python -m pytest tests/
```

Currently deployed as the `google_form_auto_reply` Docker container on this server. **`docker

created with even after the same tag is rebuilt. After code changes, rebuild and recreate the
container:
```bash
docker build -t google-form-auto-reply . && \
docker stop google_form_auto_reply && docker rm google_form_auto_reply && \
docker run -d --name google_form_auto_reply --restart unless-stopped \
  -v $(pwd)/data:/app/data \
  -v $(pwd)/configs/thinking-volt-502003-b1-14ca6f480a1a.json:/app/configs/thinking-volt-502003-b1-14ca6f480a1a.json:ro \
  google-form-auto-reply
```

Verify the new image actually took by comparing `docker inspect --format '{{.Image}}' google_form_auto_reply`
against `docker inspect --format '{{.Id}}' google-form-auto-reply:latest` — they should match.

## Domain mail auth (sumokhoe.co.kr)

SPF (`v=spf1 include:_spf.google.com ~all`) and DMARC (`_dmarc` TXT, `p=none`) were added to fix
outbound mail landing in spam; DKIM was already correctly configured. If deliverability issues
come up again, check these three DNS records first.
