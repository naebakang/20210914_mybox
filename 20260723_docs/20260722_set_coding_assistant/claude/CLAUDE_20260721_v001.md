## 작업 관행

- 기존 폴더 구조는 어디에 새 파일/폴더를 둘지 먼저 물어보지 않고 임의로 바꾸지 말 것.
- 그 외에는 되돌릴 수 있는 로컬 작업(설치, 빌드, 스크립트 실행, 현재 작업에서 명백히 필요한
  파일 생성 등)은 확인 없이 기본적으로 진행할 것.
- 예외 하나: `git config`는 절대 직접 실행하지 말고, git identity는 사용자가 직접 설정하도록
  안내할 것.
- 답변은 최대한 한글로 할 것. 명령어, 코드, 고유명사, 혹은 영문 표기가 이해하는 데 더
  직관적인/명확한 경우에 한해서만 영문을 그대로 사용할 것. 한글/영문 외의 다른 문자(한자,
  일본어 등)는 실수로라도 절대 쓰지 말 것.

## 버전 관리

- 프로젝트 버전은 `set_project.yaml`의 `name.version`에 저장되며, 형식은 `YYYYMMDD_vNNN`
  (예: `20260721_v001`) — 오늘 날짜 + 0으로 채운 3자리 카운터.
- 카운터는 날짜가 바뀌면 `001`로 리셋되고, 같은 날짜 안에서 커밋할 때마다 1씩 증가한다
  (날짜와 무관하게 계속 누적되는 카운터가 아님).
- 이 과정은 `githooks/`에 저장된 git 훅으로 자동화돼 있다 (`.git/hooks/` 자체는 git이 추적하지
  않으므로, 이 파일들을 로컬에 복사해서 사용한다):
  - `githooks/pre-commit`: `set_project.yaml`에서 현재 버전을 읽고, 위 리셋/증가 규칙에 따라
    다음 버전을 계산해서 다시 써넣은 뒤, 그 변경사항이 같은 커밋에 포함되도록 `git add`한다.
  - `githooks/post-commit`: 방금 커밋된 버전 문자열을 읽어서, 그 커밋을 가리키는 동일한
    이름의 git tag를 생성한다.
- `set_project.yaml`의 `name.version`은 직접 손으로 고치지 말고 훅이 관리하도록 둘 것.
